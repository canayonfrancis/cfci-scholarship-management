## 2. Confirmed blocker and actual network results

The existing Laravel/Symfony SMTP transport failed with
`Symfony\Component\Mailer\Exception\TransportException`. Its sanitized
classification was `certificate_verify_failed` during STARTTLS.

A separate diagnostic, without SMTP credentials and using Windows' default
certificate validation, established:

| Check | Actual result |
| --- | --- |
| TCP connection to `smtp.gmail.com:587` | PASS |
| SMTP EHLO advertises STARTTLS | PASS |
| Server accepts STARTTLS | PASS, response `220` |
| Windows TLS validation | PASS, TLS 1.3 |
| Presented certificate subject | `CN=smtp.gmail.com` |
| Presented issuer | `Avast Web/Mail Shield Root`, generated by Avast Antivirus for SSL/TLS scanning |
| PHP TLS validation using its configured CA bundle | FAIL, certificate verification rejected |
| SMTP App Password authentication | BLOCKED; not reached, so its correctness is not established |
| Actual application test-email submission | BLOCKED; not attempted after failed TLS preflight |
| Actual controlled-inbox receipt | NOT VERIFIED |

PHP uses `C:\xampp\php\extras\cacert.pem`, a readable Mozilla CA bundle dated
2026-11-05. Windows trusts the local Avast interception certificate while this
PHP trust configuration does not. The certificate was not issued directly by
Gmail's public certificate chain on this connection. Updating an unrelated
application setting or repeatedly entering the App Password cannot establish
trust in that local issuer.

No `verify_peer=false`, hostname-verification override, insecure fallback,
plain-text SMTP authentication, antivirus disablement or global trust-store
change was applied. The user is addressing the local environment through a
supported SMTP exception or administrator-approved PHP trust configuration.

The first Windows diagnostic incorrectly indexed a single-line reply as a
character and reported STARTTLS rejected. The diagnostic was corrected to
collect reply lines as an array and then confirmed response `220`. This was a
diagnostic-script issue, not an application or Gmail defect.
